# PuttingLab AR â€” B63+ Design Spec

## Tier 0 â€” B63 (Cheap Polish, ~1 day total)

Eight changes, all low-risk, all measurable. These are the "why does this feel cheap" fixes.

### T0.1 â€” Standardise spring physics to one token

**Location:** `ARPlacementView.swift` ~L362, L403, L991, L1350 (and a new `MotionTokens.swift`)
**Primitive:** `Animation` constants
**Change:** Create `MotionTokens.swift`:

```swift
enum MotionTokens {
    static let stateMachine = Animation.spring(response: 0.35, dampingFraction: 0.85)
    static let layoutShift  = Animation.spring(response: 0.40, dampingFraction: 0.85)
    static let microPress   = Animation.spring(response: 0.30, dampingFraction: 0.70)
    static let chipFade     = Animation.easeInOut(duration: 0.35)
}
```

Replace the 3 ad-hoc spring configs across the file with these tokens.
**Feel:** Eliminates the "three different spring personalities" specialist B4 flagged. Whole app reads as one motion language.
**Risk:** None â€” tuning is conservative.
**Effort:** 45 min.

## Tier 1 â€” B64 (Medium, ~2â€“3 days)

Micro-interactions, motion adds, and the empty/loading state. These are the "this feels expensive" fixes.

### T1.1 â€” Press-down scale + brightness on every primary button

**Location:** L1417â€“L1436 (`bigPlaceButton`), L1737 (Putt again), action row L1633â€“L1802
**Primitive:** Custom `ButtonStyle`:
```swift

    func makeBody(configuration: Configuration) -> some View {
        configuration.label
            .scaleEffect(configuration.isPressed ? 0.96 : 1.0)
            .brightness(configuration.isPressed ? -0.08 : 0)
            .animation(MotionTokens.microPress, isPressed: configuration.isPressed)

}
```
Apply `.buttonStyle(PressableStyle())` everywhere.
**Feel:** Apple-grade tactile response. Single biggest "this feels native" lift.
**Risk:** None.
**Effort:** 1 h (style) + 30 min (apply).

### T1.2 â€” Differentiated outcome haptics + ball-capture celebration

**Location:** L2262â€“L2269 (outcome haptic switch); new entity work near L2462
**Primitive:**
```swift
switch outcome {
case .captured:
    UINotificationFeedbackGenerator().notificationOccurred(.success)
    DispatchQueue.main.asyncAfter(deadline: .now() + 0.08) {
        UIImpactFeedbackGenerator(style: .rigid).impactOccurred()
    }
    holePulse.fire() // see below
case .lipOut:
    UINotificationFeedbackGenerator().notificationOccurred(.warning)
    DispatchQueue.main.asyncAfter(deadline: .now() + 0.05) {
        UIImpactFeedbackGenerator(style: .light).impactOccurred()
    }
case .stopped:
    UIImpactFeedbackGenerator(style: .medium).impactOccurred()
case .rejected:
    UIImpactFeedbackGenerator(style: .soft).impactOccurred()
}
```
Add a `holePulse` â€” a `ModelEntity` ring above the cup that scales 1.0â†’1.4 with opacity 1.0â†’0.0 over 600ms on capture (RealityKit `Transform` animation).
**Feel:** Brain can distinguish drain vs lip-out vs short *without looking at the screen*. The cup pulse on capture is the closest thing to confetti you can do without looking cheap.
**Risk:** Pulse entity needs `UnlitMaterial` (per the canonical memory â€” `SimpleMaterial(.white)` darkens under ARKit lighting).
**Effort:** 3 h.

### T1.4 â€” Crosshair: dynamic glow + colour-shift on confident raycast

**Location:** L1329â€“L1352
**Primitive:**

**Risk:** Spring + shadow on every frame change is fine on A14+; gate behind `confident` change only.
**Effort:** 2 h.

### T2.1 â€” First-run onboarding flow

**Location:** New `OnboardingView.swift`; gate in `PuttingLabApp.swift` on `UserDefaults.standard.bool(forKey: "hasSeenOnboarding")`
**Primitive:** 3-screen `TabView` with `PageTabViewStyle`:

## Cross-Cutting Rules (enforce in PR review from B63)

1. **No new `.spring(...)` literals** â€” must use `MotionTokens`.
2. **No new colour literals** â€” must use `ColorTokens`.
3. **Every new animation** must be wrapped in `reduceMotion ? nil : ...`.
4. **Every new interactive `View`** must have `accessibilityLabel` + `accessibilityHint`.
5. **Every new `Text` showing live numerics** must use `.monospacedDigit()`.
6. **Every new `ModelEntity`** that needs colour fidelity uses `UnlitMaterial` (per the canonical memory finding).
